# 粘贴文章分段修复设计

## 目标

粘贴进来的文章不再把细碎分段揉成一大段：听力原文的每句对话、题干与选项各自成段。

## 问题（根因）

`public/js/text.js` 的 `splitParagraphs` 只按空行（`/\r?\n\s*\r?\n/`）切分。凡是段落之间只有单个换行的粘贴内容（听力原文、题目选项、从 Word/PDF 复制的文本），整篇会被当成一段渲染成一个 `article-paragraph`。

`server/prompts.js` 的 prestudy 提示词原本用同一套空行规则给段落编号，所以服务端与前端“口径一致地错”，译文与段落索引长期对不上真正的段落。

## 方案

先按空行切块，块内逐行判断是“真正的分段”还是“排版折行”。

- 结构标记出现即断段：说话人（`M:`、`W:`、`Man:`、`Interviewer:`）、题号（`1.`、`2)`）、选项（`A)`、`B.`）、项目符号与破折号、题型词（Questions/Section/Directions/News Report…）。
- 上一行没有句末标点时，下一行以小写字母开头即为续行，直接合并。
- 上一行已结束句子时，只有整块被判定为“排版折行”才合并。折行判定：最宽行在 40–120 字符之间、至少 40% 的行排满最宽行的 85%、且过半行的行尾没有句末标点。
- 合并只用单个空格连接，不改写连字符。
- 服务端 prestudy 提示词改为直接 import 前端的 `splitParagraphs`，段落编号与阅读页一一对应（`test/prompts.test.js` 锁定这条不变量）。

## 范围与约束

- 原本用空行分段的老文章分段结果逐段不变，已缓存的段落译文与小记不会错位（`test/text.test.js` 锁定）。
- 折行判定是启发式：当一整段的最后一行正好排满整行时，可能与下一段合并。该情况概率低，代价小于把 PDF 折行拆成一堆碎段。
- 折行处若上一行以连字符结尾，按空格连接（`improve- ment`），暂不做断词还原。
- 未改动 `createArticleKey` / `normalizeArticle`，文章键与已有预研读缓存继续有效；只有段落数变化的老缓存会因长度不符被丢弃并重新生成。
