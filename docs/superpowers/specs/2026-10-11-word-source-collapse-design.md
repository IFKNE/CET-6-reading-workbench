# 单词来源引用折叠设计

## 目标

单词详情页的「来源与掌握度」不再被大量原句撑满屏幕，同时**不丢数据**（导出仍是完整的）。

## 现状与问题

`renderWordSourceList()`（`public/js/app.js:1185` 起）把**每一篇来源的每一句都渲染成 `<li>`**。

听力原文一句一段（`splitParagraphs` 按空行分段，听力材料天生一句一行），用户在手机上从一个词的不同句子里反复收录，就会让该词条的 `sources[articleId].sentences` 累积到十几二十条（`public/js/wordbook.js:10-18`：同一篇里不同句子各记一条，只对完全相同的句子去重）。再加上一个词可能出现在很多篇文章里，每个来源块各铺一堆句子——详情页因此被撑满。

## 方案：只折叠显示，不改数据

在 `renderWordSourceList` 里加两个上限（`public/js/app.js` 顶部常量，便于以后调）：

```js
const VISIBLE_SOURCES = 3;      // 最多平铺 3 篇来源，其余折叠
const VISIBLE_SENTENCES = 2;    // 每篇来源最多平铺 2 句，其余折叠
```

- 每篇来源的句子列表**按最新优先**排序后取前 2 句：复习时最想看到的是刚记下这一句的上下文，而原数组是「最早在前」的追加顺序。
- 超出部分放在 `hidden` 的兄弟节点里，配一个 `.word-source-more` 文本按钮切换显隐，按钮文案在「还有 N 句 / 收起其余原句」之间切换。
- 来源篇数超过 3 篇时同理：「还有 N 篇来源 / 收起其余来源」。
- 展开状态是**局部 DOM 状态**（不写进 `state`），所以详情页重渲染不会留下错乱的展开态，也不需要额外的全局字段。

## 不做的事

- **不动存储的数据**：`sources[].sentences` 一条都不删。`createMarkdown`（`public/js/wordbook.js:81-83`）与 Word 导出仍输出全部原句。
- 不动单词本列表行：列表行只显示「N 篇来源 · 掌握度」（`app.js:1176`），本来就不会铺句子。
- 不动来源筛选面板（`renderSourcePanel`）：那里只有计数，没有原句。

## 测试与验证

- 仓库没有 DOM 测试环境（`app.js` 无自动化覆盖），本次验证：`node --check public/js/app.js`、CSS 花括号平衡、`node --test --test-isolation=none` 保持 150 个测试全绿。
- 真机验证清单：① 打开从听力原文收录的词，详情页「来源与掌握度」不再撑满；② 每篇来源显示最新 2 句，点「还有 N 句」展开全部、再点收起；③ 来源多于 3 篇时出现「还有 N 篇来源」；④ 导出 Markdown 仍包含全部原句。
