# 文章预研读缓存：设计规格

## 目标

让六级文章在进入阅读页后尽快具备“可秒开”的全文译文与重点单词解释，减少逐词点击时等待 DeepSeek 的次数，同时控制 API 用量。

## 核心流程

1. 学习者粘贴文章并进入精读。
2. 浏览器计算文章规范化文本的稳定指纹，并查询本地预研读缓存。
3. 若命中缓存，立即渲染文章并在后台状态栏提示“已使用本地预研读”。
4. 若未命中缓存，页面先显示原文；本机服务向 DeepSeek 发起一次 `prestudy` 请求。
5. DeepSeek 在同一结构化响应中提供全文译文和适合六级学习的重点词条。
6. 结果保存至浏览器 localStorage，后续点词或查看全文译文无需重复请求。
7. 点击未被预研读覆盖的词时，保留现有单词查询逻辑；新结果追加到当前文章缓存。

## 预研读结果

每篇文章的缓存对象包含：

- `articleKey`：由规范化文章文本产生的稳定键。
- `translation`：完整、自然的中文文章译文，按原段落顺序保存。
- `vocabulary`：重点词条字典，键为小写词形。
- `createdAt`：缓存建立时间。

每条重点词条至少包含：

- 原词、词形还原、音标；
- 当前文章中最贴切的中文意思；
- 按词性和常见度排序的常见义项；
- `phrases`：最多三个与该词相关的常用短语及中文意思；
- `example`：优先取自当前文章的原句；如无合适原句，给出简短英语例句和中文意思。

## DeepSeek 筛词规则

模型仅挑选对 CET-6 阅读理解有价值、且学习者可能不熟悉的单词：中高级实义词、常见多义词、学术/抽象词和固定搭配的核心词。模型不返回冠词、代词、基础介词、极基础动词或明显简单的连接词。默认数量为 12–24 个，按“优先学习”顺序排列。

## 界面行为

- 阅读页增加“全文译文”入口；点击后立刻在批注面板展示缓存译文。
- 状态栏显示预研读进度：准备中、分析中、已缓存或缓存命中。
- 已被预研读的单词正常可点击；其词义卡片增加“常用短语”和“文章例句”部分。
- 右键“翻译”和“加入单词本”复用同一缓存；只有缓存未命中时才请求 DeepSeek。
- 预研读失败时，阅读不受影响；用户仍可逐词、逐句和逐段翻译。

## 数据与边界

- 所有缓存只保存在当前浏览器的 localStorage，不自动上传或同步。
- 缓存键由文章文本决定；改动文章内容即建立新缓存。
- 首次预研读会消耗一次 DeepSeek 调用；命中缓存则不消耗调用。
- 单篇文章限制为 10000 字符；超出时维持原有逐项翻译，不启动预研读。

## 验证

- 自动测试覆盖 `prestudy` 提示词、服务端 scope、文章键稳定性与缓存合并。
- 人工验证首次进入文章时只产生一次预研读请求；刷新或重新打开相同文章时不再请求。
- 人工验证全文译文和预研读重点词可即时显示；未覆盖单词会请求一次并写回缓存。
- 验证失败、超长文章和无 API Key 时仍能使用原有阅读功能。

## 范围外

首版不做云端缓存、跨设备同步、真正基于个人历史的词汇难度模型，也不保证“可能不会”是精确的个人能力判断；它是 DeepSeek 基于文章和六级学习目标的估计。
