# 单词即时翻译预热设计

## 目标

减少精读页面点词后的 DeepSeek 等待：已准备词立即展示，未准备词优先插队生成。

## 方案

保留现有全文预研读。预研读完成后，浏览器从首段开始提取尚未缓存的中长英文词，按每批 8 个词调用新的 `word-batch` 轻量接口；每批结果立即写进当前文章的预研读缓存。只同时运行一批，避免 API 争抢。

点击词时仍先读缓存；若该词属于未完成预热批次，则提升到下一批的最前方。单词批量请求只要求常用义、词性、短语和原文例句，详细档案继续由用户在单词详情页主动生成。

## 范围与约束

- 单篇最多后台预热 40 个候选词，首批来自首段，后续按段落顺序。
- 不处理短词、重复词、已缓存词和基础功能词。
- 所有结果保存在已有 localStorage 文章缓存；刷新或再次打开同文无需重复预热。
- API 失败不影响逐词查询；失败批次停止，不反复重试消耗额度。
